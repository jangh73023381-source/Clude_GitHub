## 1. 표준 실행 순서 — 장전 1회, 루프 먼저 → 브리핑 나중

```
T 05:30  통합 루프 (0-A 채점용 신호 → 1~2 채점 → 3~5 개선·검증관 → 6 방법·보고서)
T 06:30  0-B 오늘 관심신호 수집 (09:00 이전, 장전 윈도 내)
T 07:00  데일리 브리핑 — 방금 갱신된 analysis-method.md '확정' 규칙만 적용
T 09:00  장 시작 → T 16:00 마감 → 다음 날 05:30 루프의 채점 대상
```

- **루프가 브리핑보다 반드시 먼저.** 뒤집히면 어제 배운 것이 하루 늦게 반영된다.
- **장 마감 후 루프 실행은 폐지.** 마감 후에 돌리면 관심신호가 항상 사후수집이 된다.
- **경량 모드**: 시간이 부족하면 3~5단계만 생략하고 0~2·6단계는 반드시 수행한다.
  로그에 "경량 모드(개선 루프 이월)"로 기록하고 다음 실행에서 함께 처리.
- 정본 절차: `references/integrated-loop-runbook.md`.

## 3. 개선 루프(3~5단계)와 검증관

`scoring.new_target == true` 일 때만 수행한다.

**★ 발동 조건 (2026-10-10 CEO 결재 01 A안 — 이진 5/5 미달은 더 이상 발동 사유가 아니다)**
`new_target == true` 이고 아래 중 하나일 때만 3~5단계를 돈다.
- (i) `judge_ready.py references/lv_oos_tracker.csv lv_minus_bench` 가 '판정 가능'이고 누적 평균 `lv_minus_bench` ≤ 0 (트랙 A가 KODEX200 대비 열위)
- (ii) Rule LV 판정 시점(N*)에서 (a) MDD 또는 (b) Sharpe 가 MOM 대비 미달
그 외 날은 **관찰 모드** — 0~2·6단계(채점·기록·보고서)만 수행하고 검증관은 V1(독립 재계산)·V2만 돈다. 이진 상위10% 적중은 보조 지표로 계속 표기한다.
iteration·N 대장 무변동, 로그에 "관찰 모드(결재 01)"로 적는다. 근거: 7년 Rule LV 5/5 달성일 0.63%·평균 적중 0.55(무작위 0.54) — 이진 목표가 위험 축 규칙(LV)과 어긋나 매일 헛돌며 다중검정만 쌓였다(loop-log 2026-10-07).

1. **4단계 검증 후 반드시 검증관 `loop-goal-verifier` 호출.** Agent 도구로
   `subagent_type="loop-goal-verifier"` 스폰, 불가하면 메인 루프가 정의 파일의
   V1~V5를 **직접 그대로 수행**한다. 어느 경로든 건너뛰지 않는다.
2. 검증관은 (V1) `rank_etf.py` 로 채점 독립 재계산(룩어헤드 점검), (V2) 조기종료 방지
   게이트(v2.2 A: 시장급락=불가항력 아님 / 게이트 발동 중 불가항력 불인정 / 종목별 2출처
   없으면 학습가능 강제)를 적용한다.
3. **PASS = 후보가 손익·위험 지표(KODEX200 대비 초과·MDD·Sharpe, 7년 패널)에서 baseline 대비 개선 + 교차검증 게이트(v2.2 B)·§4 R1~R5 통과.** 이때만 방법 확정 승격(2026-10-10 결재 01로 '5/5 달성' 요건 삭제). 이진 5/5는 보조로 병기.
4. **FAIL이면 종료하지 말고 3단계로 반송.** 검증관이 기존 기각 목록과 그날 상위10% 승자
   특성을 정리해 **아직 시도하지 않은 '구별되는' 신규 가설 1개**를 지정하고 iteration +1.
5. **상한 10회(distinct)** — 2026-08-18 사용자 지시로 5회에서 확대. 소진 전에는 미시도
   개선축이 남아 있는 한 "방법 유지"로 끝내지 않는다. 소진 시 최선안 채택 + 보고서에
   "10회 내 목표 미달 — 추가 개선 필요"와 잔여 미달 사유·다음 회차 우선 시도축 명시.
   **회차당 변형 수를 늘려 상한을 채우지 않는다** — 상한 확대의 목적은 더 많은 변형이
   아니라 더 많은 *구별되는 축*이다. 축이 소진되면 10회를 채우지 않고 종료하되 그 사실을
   로그에 적는다(억지 가설은 다중검정만 늘린다).
6. 매 회차 판정(iteration·FAIL 사유·지정 신규 가설·금지 중복목록)을 `loop-log.md` 에 기록.
7. **방법 유지 허용 예외**: V2를 전부 통과하고 미적중 종목이 **개별 2출처로 입증된 진짜
   불가항력**일 때만. 이 경우에도 그날 승자 섹터·D-1 감지가능 신호를 로그에 의무 기록.

**적용 범위 — 개선·iteration·N 대장은 트랙 A(ETF 선정 레이어)에만 적용한다.**
트랙 B·트랙 C·Rule CB·Rule SU 유니버스·Rule MM 파라미터는 iteration마다 건드리지
않는다(OOS 표본 오염 방지). 트랙 B 동결값: mom20 하위컷 상위10위 / 감성컷 -0.15 / 픽 5종.

## 4. 과최적화 가드 — N 대장 · 워크포워드 · 판정 기간 N*

10회 반복 강제가 다중검정을 구조적으로 유발하므로 다음을 함께 유지한다
(상한을 5→10으로 늘린 2026-08-18 이후 이 절의 중요도가 두 배가 됐다)
(근거: `context-notes.md` §4, Bailey·Lopez de Prado).

1. 신규 distinct 규칙 시도마다 **N 대장 +1** (규칙명·전체기간 평균적중·train/test·판정 1줄).
2. in-sample 재선정 채점은 `rank_etf.py --context insample --trials <누적N>`.
   **신규 규칙의 단일일 in-sample 개선은 확정 근거로 인정하지 않는다** — 전체기간 평균이
   baseline 초과 **AND** train·test 양쪽 초과일 때만 후보 승격.
3. 방법 확정(유지 포함) 이후의 일일 채점은 `--context oos`, 워크포워드 트래커에 OOS 누적.
   방법 유효성의 실증 지표는 단일일 in-sample이 아니라 **OOS 누적 적중률**이다.
4. **3분할+잭나이프를 통과한 후보는 아래 4관문을 더 통과해야 '잠정' 이상으로 올린다**
   (2026-08-18 iteration 9 Rule SRV 가 통과 후 4관문 중 3개에서 무너진 것이 근거).
   - **R1 파라미터 고원** — 격자에서 통과가 한 점뿐이면 인공물이다(8/14 EWM 선례).
     **모든 축에 고원을 요구하되, 축이 둘 이상이면 각 축마다 따로 본다**(SRV 는 pool 축엔
     고원이 있었고 span 축엔 없었다 — 한쪽만 보면 통과로 오판한다).
   - **R2 3분할 fold** — 전·중·후 3등분 전부 baseline 초과. **fold3(최근) 열위는 탈락**이다.
     train/test 반분만으로는 최근 국면 열위가 가려진다.
   - **R3 정의 교체 재현** — 같은 개념을 다른 분류·다른 소스로 다시 만들어도 같은 파라미터에서
     재현되는가. 재현되지 않으면 그 정의에 과적합한 것이다.
   - **R4 플라시보 순열** — 라벨(업종·테마·그룹)을 무작위로 섞어 200회 이상 재계산하고
     경험적 p 값을 낸다. p 가 작아도 그것만으로 승격 근거가 되지 않는다(누적 N 이 크다).
   - **R5 꼬리 기여도 (2026-08-18 신설 · 대표본에서는 필수)** — 후보−baseline 일별 차를
     내림차순 정렬해 **상위 1·3·5·10일을 뺀 평균**과 **중앙값·윈저화 평균**을 함께 본다.
     **상위 3일을 빼서 부호가 뒤집히면 기각.** 근거: Rule TVQ 가 604일 표본에서 3분할·잭나이프·
     fold 3/3 을 전부 통과했는데 **단 1일이 이득의 63% · 3일이 108%** 였고, 상위 3일 제거 시
     평균 차가 **-0.0064%p** 로 음수가 됐다. 중앙값 차는 **0.0000%p**(후보 +0.0525 <
     baseline +0.0736 으로 오히려 열위).
     **★ 잭나이프(leave-one-out)는 대표본에서 이 결함을 못 잡는다** — 583일에서 1일을 빼도
     평균이 거의 안 움직인다. 잭나이프는 표본 20~90일 시절의 가드이며, 표본이 커질수록
     **R5 로 대체**해야 한다.
5. **판정 패널의 기본은 7년이다 (2026-08-19 신설).** `backtest/panel_ohlc_long.csv`
   (1,800거래일 2019-04~2026-07, 채점 1,779일 · 2020 코로나·2022 베어 포함)를 쓴다.
   2년 패널(`panel_ohlc_2y.csv` 604일)은 **KODEX200 누적 +206%의 단일 강세장**이라
   하락장이 없고, **R5 조차 오판을 낸다** — 같은 baseline 의 상위 3일 기여가
   2년 67% vs 7년 27.5%, 상위 5일 기여가 2년 **104%** vs 7년 43.8%였다.
   **2년만으로 승격도 기각도 확정하지 않는다.** KRX 파생 축은 KRX 데이터가 604일뿐이라
   불가피하게 2년이며, 그 사실을 판정문에 명시한다.
6. **실전 조달 가능성 검정(필수)** — 규칙이 쓰는 입력을 **선정 시각(T 06:00)에 실제로 받을 수
   있는가**를 먼저 확인한다. KRX OPEN API 는 D 일자 데이터를 **D+1 장중**에 공개한다
   (2026-08-18 실측: 20:03 KST 에 20260818 미가용, 20260814 가용). 따라서 KRX 파생 규칙은
   **[D-1] 만 실전 가능**하다. 받을 수 없는 입력으로 통과한 변형은 성과가 아무리 좋아도
   승격 후보가 아니며, **대체 조달 경로(당일 확보 가능한 대용치)로 재검정**해야 한다.

### 판정 기간 = 고정 20영업일 폐지, 잡음 기반 N*

```
N* = (1.28 × sd/|mean|)²        # 부호 판정 90% 신뢰. 하한 8 · 상한 60
```

- 판정 시점은 `python3 references/scripts/judge_ready.py <트래커> <값컬럼> [--event <컬럼>]`
  가 "판정 가능"을 낼 때다. **달력으로 20일을 세지 않는다.**
- **달력일이 아니라 이벤트 일수로 센다**(게이트가 가끔만 발동하는 규칙은 `--event`).
- 승격 조건 (a) 평균 > 0 (b) 잭나이프 하한 > 0 은 그대로.
- `judge_ready.py` 가 정본이고 `dual_score.py`·`stock15_picks.py`·`mid_momentum_shadow.py`
  가 같은 식을 인라인 복제한다. **식을 바꾸면 네 곳을 함께 고칠 것.**
- 코드·문서 어디에도 상수 20을 새로 쓰지 않는다.
- **표본이 늘면 N*도 변한다. 보고서에 인용하기 전에 재실행할 것.**

## 8. 작업 원칙

1. **단순성** — 요청한 것만 만든다. 일회성 스크립트에 요청하지 않은 옵션·추상화·"나중을
   위한 유연성"을 넣지 않는다. 단, 45초 셸 제한에 필요한 **재개(budget/멱등) 구조는 예외**.
2. **외과적 수정** — 고치라고 한 곳만 고친다. 주변 코드·주석·서식을 "개선"하지 않는다.
   관련 없는 죽은 코드는 **말만 하고 지우지 않는다.** 내 변경이 만든 고아만 정리한다.
3. **판정 기준** — 변경한 모든 줄이 사용자 요청으로 직접 추적되는가. 안 되면 되돌린다.
4. `analysis-method.md`·`loop-log.md`·`current-holdings.md`·트래커 CSV는 절차가 규정한
   항목만 갱신한다. 과거 기록을 "정리"하면 표본 이력이 오염된다.
5. **"다음 회차 과제"로 로그에만 적은 항목은 이행되지 않는다**(3회 연속 실증).
   결함을 발견하면 **그 실행 안에서 고치거나**, 못 고치면 재현 조건과 수정 위치를
   **코드 주석으로** 남긴다.
6. **하루치만 돌리는 채점 호출은 '오늘 못 하면 영원히 못 한다'.** 새 트래커를 붙일 때는
   반드시 밀린 날짜를 회수하는 경로를 함께 만든다.

  (이 플래그는 raw_·news_audit_ 를 건드리지 않아 shadow 표본이 오염되지 않는다).

- 보도량 급증을 **절대 건수**로 재면 수집 시각 차이로 전 테마가 마이너스가 된다(실측

- 홍보성·행사성 기사(`NOISE_KW`)는 감점한다.
